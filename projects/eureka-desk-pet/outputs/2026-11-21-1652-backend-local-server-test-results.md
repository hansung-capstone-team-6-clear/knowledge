- `1000086`은 본 테스트의 삭제 동의로 삭제했다. 나머지 3건은 Eureka 상태 done을 확인한 후 기존 EurekaClient.delete_task()로 테스트 업무만 정리했다.
- 테스트 ID의 SQLite 알림 기록은 기존 db.delete_reminder(), 테스트 사용자 재질문 대기는 db.clear_pending()으로 정리했다.
- 기존 미완료 업무는 테스트 전후 **7건**으로 같았고 `/api/tasks`의 기존 업무 레코드 전체(이름·마감·알림 간격·켜짐 여부 포함)를 비교해 동일함을 확인했다.
- 기존 알림 기록 **50건**의 item_id·offset_min을 배포 직전 백업과 비교해 동일함을 확인했다.
- 테스트 업무 잔존 0건, 테스트 사용자 pending 잔존 0건, 최종 `/health` 정상 및 Docker healthy 상태를 확인했다.
- 정리 도구 첫 실행은 stdin 인코딩 SyntaxError로 실행되지 않았다. ASCII Unicode escape로 수정한 두 번째 실행에서 위 정리·확인이 완료됐다. 이는 앱 기능 요청의 실패나 Eureka 쓰기 실패가 아니며 본 테스트 24건에 포함하지 않는다.

### 8. 회귀 검사 및 보존 근거

- 같은 main 코드에서 pytest **192 passed**, Ruff 통과. pytest-asyncio fixture loop scope 설정과 Starlette TestClient/httpx 관련 기존 deprecation 경고가 있었다.
- 구간 시간 원본: 로컬 eureka_list_ms·gemini_ms·total_ms는 동일 테스트 세션 로그에서 전사했고 HTTP 전체는 결과 JSON을 사용했다. 서버는 요청 ID로 결과 JSON과 컨테이너 타이밍 로그를 연결했다.
- 결과 원본 JSON과 로그는 실행 환경의 임시 결과 폴더에 남아 있으나 장기 보존을 보장하지 않는다. 이 문서에 48건의 입출력·응답 유형·구간 시간·결과와 준비 요청 2건을 전사해 보존했다. 인증 토큰·API 키·서버 .env·기존 운영 업무 내용은 포함하지 않았다.
- 기능 테스트나 문서 작성으로 백엔드 소스 파일을 새로 수정하지 않았다. 이 작업의 신규 산출물은 이 결과 문서 1개이며 신규 공통 로직·관리자·스크립트는 없다.

## Notes

- 실제 서버 텍스트 API·Gemini·Eureka·SQLite 연동은 검증했다. 실제 음성 업로드/STT·TTS 재생·Pi 화면·알람 발생은 미검증이다.
- 준비된 캐시 상태의 목록 조회이며 캐시 최초 적재, 만료/갱신 실패, 대량 목록, 동시 요청, 장시간 부하는 시험하지 않았다.
- 각 환경·기능당 3개 문항을 한 번씩 실행한 소표본이다. 장기 성공률·503 발생률·SLA 또는 p95/p99를 추정하지 않는다.
- 서버에서 수집한 경고는 한 문항의 503 재시도 1회다. 로그 범위 안의 다른 사용자 요청과 인과관계를 무조건 배제할 수는 없지만 경고가 srv1121-clarify-1의 실행 구간에 있고 최종 응답도 동일 문항으로 연결됐다.
- 기타 Backend 시간은 로컬·서버 전체에서 구간 차이값이다. 서버 등록 약 0.976~1.046초, 마감 변경 0.509~0.529초, 완료 0.532~0.622초, 삭제 실행 0.737초가 추가됐다. 이는 주로 실제 쓰기와 후처리를 포함하지만 Eureka 쓰기 단독 지연으로 표기하지 않는다.
- 서버 HTTP 전체와 Backend의 차이는 약 0.282~0.292초다. 순수 네트워크 RTT 단독 계측값은 아니다.
- 저장 위치는 기존 프로젝트의 `projects/eureka-desk-pet/outputs/`이며 별도 deskpet 프로젝트 폴더를 생성하지 않았다.
